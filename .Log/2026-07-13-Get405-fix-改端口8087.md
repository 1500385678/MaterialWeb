# 2026-07-13 · 修 GET 405 + 端口 8086 → 8087

> v1.0 启动后浏览器 GET / 返 405,定位 + 修复。

## 触发

启动 MaterialWeb v1.0 后,`python tests/smoke.py` 8/8 OK,API 都通,但浏览器 `http://127.0.0.1:8086/` 返 **405 Method Not Allowed**。

## 根因(2 个)

### 1. `core.py` 的 OPTIONS 路由"卡住"了 GET /

`server/core.py` 原本写的:
```python
@app.route('/<path:_>', methods=['OPTIONS'])
@app.route('/', methods=['OPTIONS'])
def _preflight(_=None):
    return ('', 204)
```

只给 `/` 注册了 OPTIONS 方法。Flask 看到 `/` 有 handler,但 GET 没注册 → 405。

虽然 `static_url_path='/'` 配置了静态服务,但**显式 OPTIONS 路由**优先级更高,Flask 不再走 static。

### 2. 8086 端口被 zombie 进程 46064 占用

杀掉 46064 的尝试:
- `taskkill /F /PID 46064` → 没生效
- `Stop-Process -Id 46064 -Force` → 没生效
- 进程性质:可能是 Flask debug 模式的 reloader 派生进程,父进程已死但子进程持有 socket 句柄

排查耗时:2 次失败后换策略(不再耗 token)。

## 修法

### 修法 1:加显式 GET / 路由

`server/core.py`:
```python
from flask import send_from_directory

@app.route('/<path:_>', methods=['OPTIONS'])
def _preflight_path(_):
    return ('', 204)  # /<path> 仍走 OPTIONS preflight

@app.route('/', methods=['GET', 'OPTIONS'])
def index():
    if request.method == 'OPTIONS':
        return ('', 204)
    return send_from_directory(config.STATIC_DIR, 'index.html')
```

效果:`GET /` 走 `index()` 返 index.html;`OPTIONS /` 仍返 204。

### 修法 2:端口 8086 → 8087

绕开 zombie 46064。改了 3 个文件保持一致:
- `server/config.py` `PORT = 8087`
- `scripts/daemon.py` `PORT = 8087`
- `tests/smoke.py` 注释说明

## 教训(写进 memory 候选)

1. **Flask 路由陷阱**: `static_url_path='/'` + 显式 OPTIONS 路由冲突时,显式路由赢;要给静态根路径同时支持 GET
2. **debug mode 派生的 zombie** 杀不掉时,换端口比硬刚 PID 快
3. **改端口要同步 3 个地方**: config + daemon + smoke(以后加 config_test 测端口冲突)

## 文件清单(本次修改)

- `server/config.py` · PORT 8086 → 8087
- `scripts/daemon.py` · PORT 8086 → 8087
- `tests/smoke.py` · 加端口说明注释
